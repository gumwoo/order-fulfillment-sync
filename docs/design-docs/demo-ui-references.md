# 데모 화면 레퍼런스와 방향

데모 화면(`frontend/`)을 디자이너 관점에서 다시 잡기 위해 모은 자료다.

## 지금 화면이 "AI가 만든 것처럼" 보이는 이유

Anthropic의 공식 스킬 [frontend-design](https://github.com/anthropics/skills/tree/main/skills/frontend-design)에는 AI가 만든 디자인에 흔히 나오는 특징이 정리돼 있다. 2차 화면(운영 콘솔풍)은 그 가운데 여러 개에 그대로 해당한다.

| 스킬이 꼽은 특징 | 지금 화면 |
|---|---|
| 순수 검정 대신 옅게 물든 검정(#0B0B0B, #111) | 본문 색 `#0b0b0b` |
| 작은 데이터 라벨에 고정폭 글꼴 | 사유 코드, Id, `local · mock`에 고정폭 |
| 가운뎃점으로 이은 메타 문자열(`A · B · C`) | `local · mock`, `마지막 01:47:40 · 50건 비교` |
| 가는 선, 모서리 0에 가까움, 신문처럼 빽빽한 단 | 1px 선과 3~4px 모서리만으로 나눈 화면 |
| 같은 모양 둥근 카드, 같은 옅은 그림자 (1차 화면) | 1차 화면의 KPI 카드 |
| 숫자 하나를 크게, 라벨은 작게 두는 기본 처리 | 상단 지표 줄 8칸 |

스킬은 이런 특징이 틀렸다기보다 "고른 것이 아니라 기본값"이라는 점이 문제라고 한다.
그래서 주제(주문·출고 동기화, 장애 복구)에서 디자인을 끌어내라고 한다.

## 방향 (제안)

주제는 "장애가 나도 주문 상태가 저절로 맞춰지는 과정"이다. 화면이 보여 줄 한 가지는 **복구 타임라인**이다.

- 기억에 남을 한 곳: 복구 타임라인 그래프
  - Vercel처럼 사건을 그래프 위에 문장으로 적는다.
  - 예: "웹훅 30% 유실 → 불일치 37건 → 21초 만에 0"
  - 장애를 넣은 시점에 세로 표시를 하고, 불일치가 있던 구간을 옅게 칠한다.
- 지표: Tremor처럼 카드 없이 놓는다.
  - "원장과 일치 43 / 50"은 진행 막대로 보인다.
  - 큐, DLQ, 사람 처리 대기는 값과 짧은 비교 문구로만 둔다.
- 장애 주입: 도구 줄을 상시 펼치지 않는다.
  - "장애 시나리오" 버튼을 누르면 오른쪽 패널이 열린다.
  - 시나리오는 프리셋(웹훅 유실, 429 폭주, 출고 후 취소)과 세부 설정으로 나눈다.
- 목록: Tremor 상세 표처럼 만든다.
  - 상태는 배지(미처리, 해결됨)로 보인다.
  - 사유는 한국어 이름을 보이고, 코드는 마우스를 올리면 보인다.
  - 필터 칩을 두고 숫자 열은 오른쪽 정렬한다.
- 서체: Pretendard 한 가지만 쓰고 숫자는 tabular. 고정폭 글꼴은 쓰지 않는다.
- 색
  - 차가운 회색 중립 4단계와 브랜드 파랑 하나를 쓴다. 상태색은 정상·주의·문제로만 쓴다.
  - 본문 검정은 물든 검정 대신 회색 계열 진한 색을 쓴다.
- 문구: 운영자 말로 쓴다 (2026-11-12 사용자 피드백 "개발자스러운 용어 너무 많음")
  - 대사는 쇼핑몰과 비교, 원장은 쇼핑몰 기준, 불일치는 상태가 다른 주문
  - 웹훅은 주문 알림, 429는 요청 제한, DLQ는 자동 처리 실패, 큐는 자동 처리 대기
  - 3PL은 물류 창고, 미연동은 창고 등록 실패, 충돌은 확인 필요
  - 원래 용어는 title로 남겨 마우스를 올리면 보이게 한다
  - 서버가 주는 오류 원문(API 응답 JSON 등)은 화면에 그대로 내지 않는다
  - 버튼은 누르면 무슨 일이 생기는지 쓴다
    - "초기화" 대신 "데모 데이터 지우기"(확인 창 띄움), "다시 처리" 대신 "창고에 다시 등록"
  - 비슷한 말을 겹치지 않게 한다
    - "처리할 작업"과 "사람이 처리할 일"이 헷갈려 앞쪽을 "자동 처리 대기"로 바꿨다
  - 내부 번호(#14) 대신 주문번호를 보인다
- 금지
  - 가운뎃점 메타 문자열
  - 모든 블록을 같은 카드로 감싸기
  - 화살표를 붙인 버튼 문구
  - 대문자 라벨
