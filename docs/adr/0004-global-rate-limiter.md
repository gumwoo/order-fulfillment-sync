# ADR-0004 전역 레이트 리미터, 429는 DLQ로 보내지 않음

- 상태: 채택
- 날짜: 2026-11-11

## 맥락
샵바이 서버 API는 초당 100회 토큰 버킷이고, 남은 양이 없으면 `ratelimit-available-level: EXHAUSTED`를 준다. 웹훅 처리 시리즈 4편에서는 인스턴스별 제한의 합이 한도를 넘었고, 429 재시도가 receive count를 소모해 메시지가 DLQ로 빠졌다.

## 결정
Redis Lua 토큰 버킷 하나를 모든 인스턴스가 공유한다(80/s). EXHAUSTED 헤더를 받으면 버킷을 비운다. 429는 visibility timeout을 늘려 재수신하고, 재시도 횟수를 별도로 센다.

## 검토한 대안
- 인스턴스별 Resilience4j RateLimiter: 인스턴스 수가 늘면 합계가 한도를 넘는다.
- 429도 일반 실패로 처리: 일시적 대기 신호인데 DLQ가 쌓인다.

## 결과
Redis가 죽으면 호출을 멈추고(보수적), 장애 해소 후 재조회 경로가 따라잡는다.
