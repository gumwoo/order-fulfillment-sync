# ADR-0008 3PL 일시 장애는 재발행으로 다시 시도한다 (최대 20회)

- 상태: 채택
- 날짜: 2026-11-11

## 맥락
ADR-0007은 샵바이 429만 재발행으로 다시 시도하고, 그 외 실패는 SQS 재전송(`maxReceiveCount`, 기본 5)에 맡긴다.
3PL(파스토 규칙 mock) 호출은 출고 요청·취소 경로에 있다. 3PL이 몇 분 동안 응답하지 않으면 다음 문제가 생긴다.
- visibility timeout(30초) × 5회 안에 DLQ로 가서, 3PL이 회복된 뒤에도 사람이 꺼내야 한다.
- 설계 4.7은 3PL 타임아웃을 지연 재처리로 흡수한다고 정했다.

## 결정
- 3PL 호출 실패는 모두 `TplException`으로 통일한다: 5xx, 예상 밖 4xx, 연결 거부·타임아웃(`ResourceAccessException`).
  - 예외: 등록 422(옵션명 매핑 없음)는 미연동으로 기록한다.
  - 예외: 취소 409(피킹 이후 취소 불가)는 업무 결과로 처리한다.
- worker는 `TplException`을 받으면 `attempt`를 올린 새 메시지를 지수 백오프(1, 2, 4, 8, 16, 30초 …)로 재발행한다.
  - 20회를 넘으면 재전송으로 돌려 결국 DLQ로 보낸다.
- 재발행은 원래 메시지를 지우고 새 메시지를 보내므로 receive count를 올리지 않는다 (ADR-0007과 같은 방식).

## 검토한 대안
- **SQS 재전송만 사용:** 3PL 장애가 2~3분이면 DLQ로 간다.
- **무한 재발행:** 3PL 쪽이 영구적으로 거절하는 요청(잘못된 데이터)이 끝없이 돈다.

## 결과
- 3PL 장애가 약 10분 안에 회복되면 사람 개입 없이 처리된다 (30초 상한 기준 20회).
- 영구 실패는 20회 뒤 DLQ에서 보인다.
- 재시도 중에는 같은 주문옵션 메시지가 여러 번 처리된다. 출고 요청·취소는 단계별로 저장하므로 결과는 같다.
