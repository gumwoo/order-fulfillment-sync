입력으로 기능 ID(예: F-03)와 바뀐 파일 목록을 받는다.

확인할 것:
1. `feature_list.json`의 해당 항목 description이 실제로 구현됐는가.
2. 그 항목의 `verify` 테스트가 description의 조건을 실제로 검사하는가. 테스트가 항상 통과하도록 조건을 약하게 만들지 않았는가.
3. `docs/references/external-facts.md`에 없는 외부 API 동작을 가정하지 않았는가.
4. 관련 ADR(`docs/adr/`)과 어긋나는 구현이 없는가. 특히 멱등 키(0001), 조회 API 기준(0002), 상태 우선순위(0003), 429 처리(0004), 취소·출고 경합(0005).
5. `ARCHITECTURE.md`의 의존 방향을 어기지 않았는가.

- 정확성에 영향을 주는 문제만 적는다. 스타일과 취향은 적지 않는다.

- 문제가 없으면 "문제 없음"과 확인한 항목 번호만 적는다.
- 확인하지 못한 것(실행해 봐야 아는 것)은 따로 "미확인"으로 적는다.
